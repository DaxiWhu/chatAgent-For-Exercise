# 服务概览与接口

## 这是什么

chatAgent 是一个基于 LangGraph 构建的检索增强生成（RAG）智能体服务。它的核心特点是
把「生成 → 自审 → 人工审核 → 修订」做成了图上的一个环：模型先给出草稿，评审节点打分并提意见，
分数不达标就进入人工审核环节，由人改写意见后再让模型出完整的新版本。

服务对外提供流式（SSE）与非流式两类接口，可以直接被 Web 前端、命令行或其它服务调用。

## 启动方式

**必须使用 `python -m app.serve` 启动，不要用裸 `uvicorn app.main:app`。**

原因在于检查点（checkpoint）。所有端点内部都使用 `await graph.astream(...)` 与
`await graph.aget_state(...)`，因此持久化必须使用异步的 `AsyncPostgresSaver`；
而 psycopg 的异步模式**不支持 Windows 的 ProactorEventLoop**。uvicorn 在 win32 且没有子进程时
会故意选择 Proactor 事件循环，所以 `app/serve.py` 通过 `--loop app.serve:loop_factory`
注入了一个自适应的事件循环工厂。

注意：`asyncio.set_event_loop_policy(...)` 在 uvicorn 下是无效的，只有 `--loop` 那条工厂路径有效。
该工厂必须做到「无参调用即返回一个 loop 实例」。

## 端点清单

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/v1/chat` | SSE 流式对话 |
| POST | `/v1/review` | 提交人工审核结果（接受或修订） |
| POST | `/v1/chat/resume` | 从被中断的会话继续生成 |
| GET | `/v1/reviews` | 列出待审核记录 |
| GET | `/v1/sessions/{thread_id}` | 查询会话状态快照 |
| GET | `/health/live` | 存活探针，不依赖外部服务 |
| GET | `/health/ready` | 就绪探针，真探 LLM 配置、数据库、向量后端、检查点 |
| GET | `/metrics` | Prometheus 文本指标 |

`POST /chat` 与 `POST /review` 是不带版本号的旧路径，已标记 `deprecated`，仅为兼容老客户端保留。

## SSE 事件类型

`/v1/chat` 与 `/v1/chat/resume` 返回 Server-Sent Events，事件类型包括：

- `token` —— 逐段生成的正文，**保持裸文本，不做 JSON 包装**
- `citations` —— 可回溯的引用，描述「上面这段回答依据了什么」
- `need_review` —— 需要人工审核，附带草稿、评分与评审意见
- `budget_exceeded` —— 单请求 token 预算耗尽，生成被提前终止
- `timeout` —— 请求级总超时耗尽，附已产出的字符数
- `done` —— 正常结束
- `error` —— 异常收尾

`token` 之外的结构化事件一律经过 `json.dumps` 序列化。这一点容易出错：
如果直接下发 Python dict，线上会变成 Python 的单引号 repr，JavaScript 与 Go 客户端全部无法解析。

## 鉴权与身份

身份模型分三档，按配置自动选择：

1. 配了 `TENANT_KEYS`：租户由 API Key 反查得出，请求头 `X-Tenant-Id` 只用于核对，
   不一致时返回 **403**。这是唯一可信的多租户模式。
2. 只配了 `SERVE_API_KEY`：属于自报模式，启动时会打告警。此时 `X-Tenant-Id` 由客户端自行声称。
3. 两者都没配：身份为 `anonymous`。

`REQUIRE_AUTH` 与 `ENABLE_DOCS` 由 `APP_ENV=production` 推导；生产环境且没有任何 Key 会**拒绝启动**。

鉴权请求头为 `X-API-Key`，租户声明为 `X-Tenant-Id`。

## 请求体

对话请求包含两个字段：`thread_id`（会话 id）与 `message`（用户输入）。
`thread_id` 会被用作检查点主键、限流桶键与会话归属表主键，因此有长度上限约束。
