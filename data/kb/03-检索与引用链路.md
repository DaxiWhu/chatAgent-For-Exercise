# 检索与引用链路

## 格式分流

语料加载的总入口是 `load_chunks`，它按扩展名把文件分流到不同链路：

- **`.pdf`** —— 由 Docling 解析；Docling 不可用时自动降级到 pdfminer 链路。
  Docling 路径按 token 计预算，pdfminer 路径按字符计块长。
- **`.docx`** —— 同样走 Docling 双路线：正文走文档模型，另外解 zip 包提取图片、图表与 OLE 对象。
  不可用时降级到 python-docx（此时只能拿到正文，会丢掉媒体部分）。
- **其它格式**（`.md` / `.txt` / `.csv` / `.xlsx` / `.pptx` / `.json` 等）——
  先做**结构化解析**成块，再切分。

第三类刻意不是「先拍平成一段文本再切」：csv 有表头、xlsx 有工作表、pptx 有页序、
markdown 有标题路径、json 有记录边界。拍平之后就永久丢失了这些结构，
引用也就无法回溯到具体位置。

单份文件解析失败只跳过并告警，不会中断整批语料。

## 遍历规则

`load_chunks` 递归遍历语料目录下的所有文件。这里有一个容易踩的点：
遍历使用 `glob` 的 `**` 模式，而 `glob` 的 `*` 与 `**` **都不匹配以点号开头的目录**。

这正好是缓存目录得以安全共处的原因——解析缓存默认放在 `<语料目录>/.parse_cache`，
上下文缓存默认在 `.ctx_cache`，媒体导出在 `.media`，图像描述缓存在 `.vlm_cache`，
它们都以点号开头，不会被当成语料读进去。

## 切分

非 PDF 格式默认按结构感知切分：块长上限 300 字符，块间重叠 50 字符
（分别由 `RAG_CHUNK_SIZE` 与 `RAG_CHUNK_OVERLAP` 控制）。

`load_chunks` 的收尾固定三步，顺序有讲究：先应用上下文前缀，再挂父块，最后打加载摘要。
顺序刻意是「先上下文前缀、后父块」，因为前缀是喂给嵌入模型的**检索用文本**，
父窗是喂给生成模型的**生成用文本**。如果反过来，父窗里就不含前缀，
于是「被检索的内容」与「被生成的内容」成了两套文本，出问题极难解释。

## 检索后端

支持三种后端：

1. **tfidf** —— 纯本地、零外部调用、结果确定，适合做 CI 门禁与降级兜底。
2. **pgvector** —— 通过 PostgreSQL 的向量扩展做语义检索。
3. **混合检索** —— 多路召回后用 RRF（倒数排名融合）合并，再经 rerank 精排。

嵌入与重排调用都经过熔断器保护（`src/rag/resilience.py` 的 `guarded_call`）：
连续失败达到阈值后快速失败，避免在依赖已经不可用时继续堆请求。

## 引用与可回溯

每条回答都带 citations，字段包括序号、来源文件名、页码或页范围、章节路径、
保真原文节选、表格网格与图片路径，以及用于回溯的 `chunk_id`。

引用在 token 之后、`done` 之前下发：它描述的是「上面这段回答依据了什么」，
顺序上必须在正文之后才有意义。用户点开引用就能回到原文件核对，而不是只能相信模型。

跨页内容用页范围表示，图片类引用会带上落盘路径与可见文本转录。

## 租户隔离

**过滤值一律取身份里的租户，而身份只剩一条来源：已验签的 JWT 载荷。**
请求头 `X-Tenant-Id` 不参与取值，只能与载荷核对（不符返回 403）。

- 载荷里有租户 ⇒ 按该租户过滤，只召回该分区的片段；
- **载荷里没有租户**（空串）⇒ 落到**公共租户**（由 `RAG_TENANT` 指定，
  本项目用 `public`）—— 也就是"没有租户的账号只能读我们提供的公共文档，
  别的租户的读不到"；
- `RAG_TENANT` 也留空 ⇒ 落到哨兵值 `NO_TENANT_SENTINEL`，**什么都召回不到**。

**空串在这里的含义是"什么都看不到"，不是"不加过滤"。** 这一点在 2026-10-05 反转过：
更早的口径是"空串 ⇒ 不加过滤"，等于给每个还没分配租户的账号开了整库只读权限，
而自助注册出来的账号恰好都没有租户。

因为租户取自令牌而客户端无法自报，`X-Tenant-Id` 现在只是一个**一致性确认**：
它影响不了数据分区，只在"运维把令牌发错了租户"时把问题当场暴露出来。

租户通过 `tracing.build_run_config(rag_tenant=...)` 写进运行配置的 `configurable` 段，
**不写进图状态**：租户是运行参数，写进状态会被检查点持久化，续跑时可能带上过期值。

检索器按租户分片缓存且有上限（`RAG_TENANT_CACHE_MAX`，默认 8，采用 FIFO 淘汰），
因为租户字符串来自请求，无上限缓存等于一个可被利用的内存放大面。

## 语料为空时的行为

语料目录不存在或为空时，`load_chunks` 会**静默返回空列表**。服务照常启动、探针全绿、
SSE 照常可连，但检索恒无结果、回答里没有任何引用。

为此加载完成后会检查片段数量，为 0 时打一条明确的 warning，提示优先检查语料目录是否挂载、
路径是否与 `DOCS_DIR` 一致。没有这条告警就只能靠用户反馈「答得不对」才发现问题。
