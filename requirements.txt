# 用户鉴权（第二档，app/auth.py）：OIDC / JWT 验签。
# PyJWT 做编解码与算法实现，[crypto] 拉入 cryptography —— JWKS 里的
# RS256/ES256 验签必须靠非对称实现，纯 Python 做不到。
# 只用本地用户表 + 自签会话（HS256）时其实用不到非对称部分，但不装就**无法验
# 外部 IdP 的 token**；列成硬依赖的理由同 redis：宁可让缺失直接暴露，
# 也不要"配了 OIDC 却静默不生效"（那会表现为"用户全都登不上"而无一行报错）。
# 注意 PyJWT 2.10 起自己会拒绝"用非对称公钥做 HMAC 密钥"，这层防护**不能依赖**
# （换版本就没了），服务端的算法白名单才是防线（见 app/auth.py 的 verify）。
#
# ⚠️ 下限 2.14.0 是安全修复版（CVE-2026-102268，CRITICAL：公钥处理不当导致
#    认证绕过）。我们用的是 HS256 对称密钥，该路径理论上走不到 —— 但"这次走不到"
#    不是可以长期挂着 CRITICAL 的理由：`verify` 支持多种算法，而限制算法集合是
#    配置项，配置一改就成立。
