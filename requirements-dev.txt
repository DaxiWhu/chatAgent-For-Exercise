# 开发与 CI 用的静态检查 / 覆盖率工具。
#
# ⚠️ **不进生产镜像** —— `deploy/app/Dockerfile` 只装 `requirements.txt`。
#    这里的东西多一个字节都不该出现在运行时容器里（那也是攻击面）。
#
# 为什么版本**钉死**（`==`）而不是 `>=`
# ------------------------------------
# 这几个工具的**判定结果会随版本变**，不是"新版本更准一点"那么温和。实测：
# ruff 0.16 的默认规则集比旧版宽得多，同一份代码从 0 个报错变成 746 个。
# 不钉版本的话，"CI 是绿是红"取决于流水线**哪天**跑的 install，
# 而不是取决于代码 —— 那正是这一层最不该有的不确定性。
#
# 与 `requirements.lock` 的关系
# ----------------------------
# 这份文件**不参与** `scripts/lock_requirements.py` 的一致性门禁（那只管
# `requirements.txt`）。工具版本在这里直接钉死，不需要再经一层 lock。
ruff==0.17.4
mypy==2.4.1
pytest-cov==7.1.0
